## Context

The repository builds a browser game with Phaser, TypeScript, and Vite. The
entry point creates `Phaser.Game`, and deployment publishes the Vite `dist/`
output.

## Decision

Treat the application as a frontend-only static application. Runtime state and
persistence remain in the browser unless a backend is explicitly approved.

## Rationale

The reviewed architecture names static hosting, the package deploy script uses
GitHub Pages output, and repository guidance explicitly excludes an implicit
server, database, API, or authentication layer.

## Consequences

Features must work within the browser runtime and static asset pipeline. A
server-side capability is an architectural change, not an assumed dependency.
