## Context

Repository guidance had started to duplicate counts, inventories, architectural
rationale, roadmaps, and history across agent files, directory context, human
documentation, and the `.shadow/` graph. Duplicated claims drift when code,
tooling, or plans change in one place but not the others.

## Decision

Use one owner per documentation information type:

- `AGENTS.md` owns the agent quick-reference architecture, commands, workflows,
  common tasks, and anti-patterns.
- `CONTEXT.md` files own nearest-directory inventories and local conventions.
- `.shadow/` owns durable decisions, rationale, status, evidence, and feature
  mappings.
- `docs/architecture.md` owns the human narrative of the current architecture.
- `docs/plan.md` owns the feature roadmap.
- Root `plan.md` owns the engineering revamp plan when that file is present.
- `docs/CHANGELOG.md` owns completed history.

When the same information appears in two owner classes, keep it in the owner and
remove or replace the non-owner copy with a pointer to the owner.

## Rationale

The split keeps agent-facing material concise, local context close to files,
architecture rationale evidence-backed, roadmap material separate from completed
history, and human narrative readable. It also gives future documentation drift
work a deterministic way to decide which duplicate claim to delete.

## Consequences

Documentation updates must check the owner for the information type before adding
new copies elsewhere. Cross-links are preferred over duplicated inventories or
counts. Future drift passes should move duplicated detail to the owning document
rather than synchronizing multiple copies by hand.

## Unknowns

The root `plan.md` owner is part of the policy, but this worktree does not
currently contain that file; the policy applies if it is restored or created by a
separate revamp-planning change.
