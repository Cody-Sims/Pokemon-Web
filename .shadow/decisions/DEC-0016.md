## Context

The repository now relies on automated checks for TypeScript, tests, data/maps, agent guidance, shadow records, lint/format drift, coverage, deterministic generated assets, bundle budgets, and browser flows.

## Decision

Use `package.json` scripts and CI as the canonical quality-gate contract: Vitest unit/integration/replay tests with setup and coverage thresholds, map validation, agent and shadow validators, report-only lint/format checks where configured, production build, build-purity diff check, bundle-size check, E2E, and scheduled fuzz.

## Rationale

`tests/vitest.config.ts` defines setup files, test includes, V8 coverage, and thresholds. CI runs lint, format check, map validation, agent validation, shadow validation, tests, coverage, build, build purity, bundle budgets, E2E, and scheduled fuzz jobs using Node 22 from `.nvmrc`.

## Consequences

Changes should run the narrowest relevant local checks before the broader required validators. A passing local build/test does not replace CI-only gates such as build purity, bundle budgets, scheduled fuzz, or browser E2E when those areas are affected.

## Unknowns

Formatting and npm audit are currently non-blocking in workflow comments, and coverage thresholds are intentionally low baseline thresholds rather than a claim of comprehensive coverage.
