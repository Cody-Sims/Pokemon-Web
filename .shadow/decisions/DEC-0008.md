## Context

The game combines pure logic, singleton state, browser rendering, data
cross-references, maps, and interactive flows with different validation costs.

## Decision

Verify changes in layers: focused unit and integration tests, full Vitest runs,
build and type checks, browser E2E checks, and domain checks such as map
validation. Keep randomized checks reproducible with seeded or fixed randomness.

## Rationale

The test architecture defines unit, integration, E2E, replay, and fuzz layers.
Package scripts expose those checks, while global test setup seeds the game RNG
and fixes `Math.random` for deterministic runs.

## Consequences

Run the narrowest relevant check first, then the broader required gates. Scene or
UI changes need browser coverage, and map changes need map validation.
