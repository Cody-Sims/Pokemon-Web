## Context

Phaser scenes have independent lifecycles, while party, progress, player,
statistics, and save data must survive scene transitions.

## Decision

Keep persistent game state in singleton managers rather than scene instances.
`GameManager` provides a singleton facade over focused state managers, and
`SaveManager` serializes that state to browser storage.

## Rationale

The implementation exposes `getInstance()` access, central reset and
serialization paths, and state-focused sub-managers outside the scene lifecycle.
Repository guidance also assigns persistent state to `GameManager`.

## Consequences

Scenes read and mutate durable state through manager APIs. Tests must reset
singletons where isolation requires a fresh process-level instance.
