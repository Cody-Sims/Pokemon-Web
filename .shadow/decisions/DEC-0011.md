## Context

String scene keys, arbitrary scene init payloads, and open-ended event names made cross-scene changes hard to check at compile time.

## Decision

Keep scene keys in the `SceneKey` literal registry, route scene operations through `SceneRouter` when possible, describe init payloads in `SceneDataMap`, and constrain global `EventManager` names to `keyof EventMap` with typed payload tuples.

## Rationale

`scene-router.test.ts` verifies the scene-key registry covers the configured scene list, and `SceneRouter` uses `SceneDataArgs<K>` to type scene start/launch data. `EventManager` now stores listeners by the closed `EventName` union and emits only payloads declared by `EventMap`.

## Consequences

New scenes and global events must extend the typed registries before callers can use them. Direct Phaser string calls may remain in legacy code, but new cross-scene contracts should avoid untyped ad hoc strings.

## Unknowns

The migration is partial: searches still find many literal scene names in scene files, and Phaser-local `this.events.emit()` calls are not part of the closed global `EventMap` contract.
