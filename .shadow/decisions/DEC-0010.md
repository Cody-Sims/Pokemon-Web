## Context

Menu, dialogue, HUD, and battle UI code need consistent navigation, panels, progress bars, typography, touch handling, and cleanup across scenes.

## Decision

Use the shared UI layer for new menu and dialogue work: `SelectableController` for list/grid selection state, `TextBox` for typewriter dialogue and battle messages, `ProgressBar` and themed panel presets for bars and panels, and `theme.ts` tokens for colors, spacing, and fonts.

## Rationale

The UI instruction file requires theme tokens, constructor-injected scene references, no direct game-state reads, and barrel exports. The selectable-controller tests verify reusable navigation behavior independently of scene rendering.

## Consequences

New menus should not create bespoke cursor, scroll-window, or panel systems when a shared widget covers the behavior. Existing scenes can migrate incrementally, but new abstractions must stay scene-agnostic and receive all game state from callers.

## Unknowns

The migration is partial. Several existing menu and battle scene paths still contain hand-written UI logic, and no visual regression record proves every scene has adopted the canonical widgets.
